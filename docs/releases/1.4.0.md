# Rony.Net 1.4.0

Test mutual TLS and check what a client negotiated, listen on IPv6, dual-stack and Unix domain sockets, describe a mock in a JSON file, and run it without writing code: the new `rony` tool serves a file, records a real server and replays the recording.

**No breaking changes:** code written for 1.0 to 1.3 compiles and behaves the same. One behaviour is stricter: a length-prefixed message with a negative length now closes that connection instead of buffering without end.

```console
dotnet add package Rony.Net --version 1.4.0
dotnet tool install --global Rony.Net.Cli
```

## ✨ What's new

### TLS extras
```csharp
using var serverCertificate = TestCertificate.CreateSelfSigned();
using var clientCertificate = TestCertificate.CreateSelfSigned("my-client");
using var server = new MockServer(new TcpServerSsl(0, serverCertificate, SslProtocols.Tls12) { RequireClientCertificate = true });

var connection = await server.WaitForConnectionAsync();
connection.Should().HaveUsedTls(SslProtocols.Tls12)
    .And.HaveServerName("localhost")
    .And.HavePresentedClientCertificate(clientCertificate);
```
- `TestCertificate.CreateSelfSigned()` replaces the helper you had to copy into your tests. Nothing is added to a certificate store.
- `RequireClientCertificate` adds mutual TLS. Any presented certificate is accepted unless `ClientCertificateValidator` rejects it; a rejected client fails the handshake and is logged.
- `connection.Tls` gives the negotiated protocol, the SNI server name and the client certificate. When a rejected client notices depends on the operating system, so wait for it on the server side.

### IPv6, dual-stack and Unix domain sockets
```csharp
new MockServer(new UnixSocketServer());                              // Unix domain socket; the file is listener.Path
new TcpServer(IPAddress.IPv6Any, 0) { DualMode = true };             // IPv4 and IPv6 on one port (UdpServer: new UdpServer(endPoint, dualMode: true))
```
`UnixSocketServer` has the features of `TcpServer`: framing, persistent connections, pushed messages and failure simulation. It has no TLS, and a reset is a plain close because a Unix socket has no RST. The socket file exists only while the server accepts connections.

### Configuration files
```csharp
// mock.json: { "version": 1, "rules": [ { "request": "PING", "reply": "PONG" } ] }
using var server = MockServer.FromFile("mock.json");   // listener and rules from the file
server.Start();
```
A file describes the listener (TCP, TLS, UDP or Unix socket, with framing) and the rules: exact, regular expression and JSON matching, greetings, sequences, delays, disconnects, resets and scenario states. A mistake is a `FormatException` that names the place, and unknown properties are rejected so typos are found. The server you get back can still be extended in code and checked with `server.Should()`.

### The `rony` tool
```console
rony run mock.json                                   # serve a configuration file (Ctrl+C stops it)
rony validate mock.json                              # check a configuration file, for example in CI
rony record --target api.test:5000 --out login.json  # record a real server through a proxy
rony replay login.json                               # serve the recording
```
The new `Rony.Net.Cli` package is a .NET tool for using the mock outside of .NET tests: as a stand-in for a service during local development, for a team or a CI job that does not use .NET, or in a container (the repository has a `Dockerfile` to build an image; none is published). It listens on loopback unless told otherwise and is meant for development and test networks; see [Limits and security](https://github.com/archofthings/Rony.Net/wiki/Standalone-Server#limits-and-security).

### Buffer limit
`MaxBufferedBytes` on the TCP, TLS and Unix socket listeners limits what one connection may buffer while waiting for a complete message. It is unlimited by default, as before; servers from a configuration file and `rony replay` use 16 MiB.

## 🐛 Fixed
- A length-prefixed message with a negative length made the connection buffer everything that followed. The connection is now closed and reported.
- Connection details in log lines (TLS server name, client certificate subject, remote address, error messages) are escaped, so a client cannot inject lines or terminal sequences into the log.

## 🧹 Repository
- A security review of the whole release; its findings are fixed or listed under [Known Issues and Limitations](https://github.com/archofthings/Rony.Net/wiki/Known-Issues).
- A security policy (`SECURITY.md`) with private vulnerability reporting, Dependabot for the pinned actions and Docker images, secret scanning and CodeQL.
- The workflows pin their actions to commit SHAs, CI runs with a read-only token, and the release is created with the GitHub CLI instead of a third-party action.

## 📦 Packages
`Rony.Net`, `Rony.Net.Xunit`, `Rony.Net.Xunit.v3`, `Rony.Net.NUnit`, `Rony.Net.MSTest` and `Rony.Net.Cli` (the `rony` tool), all at 1.4.0. `Rony.Net.Cli` is new. The test framework packages have no changes of their own.
