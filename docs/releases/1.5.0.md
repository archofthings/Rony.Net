# Rony.Net 1.5.0

The `rony` tool grows up: a test in any language can now ask it what it received and steer it, it reloads its rules when the file changes, and it is published as a Docker image with a Testcontainers module for .NET tests. The library gets the same abilities in code, plus six fixes.

**No breaking changes:** code written for 1.0 to 1.4 compiles and behaves the same. Three things change in the tool: it keeps only the last 10000 received requests and connection records (`--keep 0` for all), `rony validate` no longer opens a socket, and a `unix` configuration without `server.path` now runs.

```console
dotnet add package Rony.Net --version 1.5.0
dotnet tool install --global Rony.Net.Cli
docker pull ghcr.io/archofthings/rony:1.5.0
```

## ✨ What's new

### Ask the tool what it received
```console
$ rony run mock.json --journal requests.jsonl --control 0
Listening on tcp 127.0.0.1:41208
Control on 127.0.0.1:41210

$ printf '%s\n' '{"command":"requests"}' '{"command":"state","set":"authenticated"}' | nc 127.0.0.1 41210
{"ok":true,"requests":[{"seq":1,"time":"2026-10-04T12:34:56.789+02:00","connection":1,"remote":"127.0.0.1:50123","matched":true,"text":"PING"}],"last":1}
{"ok":true,"state":"authenticated"}
```
- `--journal <file>` appends every received request as one line of JSON, written at once, so another process can read it while the server runs.
- `--control <port>` opens a control endpoint: one JSON command per line, one reply per line. `requests` lists what was received (with `"after": <seq>` only the newer ones), `clear` forgets it, `state` reads the scenario state and `"set"` changes it, which switches every rule that depends on a state in one step.
- The control endpoint has no authentication and listens on `127.0.0.1`; `--control-address` binds it elsewhere, for example to reach it from outside a container.
- Both options work for `rony run` and `rony replay`. Details: [Journal](https://github.com/archofthings/Rony.Net/wiki/Standalone-Server#journal) and [Control endpoint](https://github.com/archofthings/Rony.Net/wiki/Standalone-Server#control-endpoint).

### One file, many places
```console
rony run mock.json --port 5000 --address 0.0.0.0   # the same file on another port and address
rony run mock.json --watch                         # reload the rules when the file changes
```
`--port` and `--address` override the file. `--watch` reloads the rules about a second after you save, without dropping open connections; a file with a mistake is reported and the previous rules stay. Changes to the `server` section still need a restart.

### A Docker image
```console
docker run --rm -p 127.0.0.1:4000:4000 -v "$PWD/mocks:/config:ro" ghcr.io/archofthings/rony run /config/shop.json --address 0.0.0.0
```
The tool is published for `linux/amd64` and `linux/arm64` as `ghcr.io/archofthings/rony` and on Docker Hub as `mojihub/rony`, with the tags `1.5.0`, `1.5`, `1` and `latest`. It needs no .NET on the machine and works with Docker Compose; see [Docker](https://github.com/archofthings/Rony.Net/wiki/Standalone-Server#docker).

### Testcontainers
```csharp
await using var rony = new RonyBuilder()
    .WithConfigurationFile("mocks/shop.json")
    .Build();
await rony.StartAsync();

using var client = new TcpClient(rony.Hostname, rony.Port);
// ... the system under test talks to rony.Hostname:rony.Port ...
var requests = await rony.GetReceivedRequestsAsync();
await rony.SetStateAsync("outage");
```
The new package `Rony.Net.Testcontainers` starts the image from a test, copies the configuration in and waits until the tool listens. It needs Docker where the test runs and Testcontainers 4.15.0 or later. A `unix` configuration is not supported and a `udp` configuration needs its own port binding.

### The same in code
```csharp
using var server = MockServer.FromFile("mock.json", new ConfigurationOverrides { Port = 0 });
MockServer.ValidateFile("mock.json");   // throws FormatException with the place of the mistake; opens no socket
server.ReloadFile("mock.json");         // new rules; connections, received requests and the scenario state are kept

server.Mock.MaxReceivedRequests = 1000;
server.MaxConnectionRecords = 1000;
server.RequestReceived += (sender, request) => journal.WriteLine(request.ToJson());
```
- `ConfigurationOverrides` replaces the address and port of a configuration; `ValidateFile` / `ValidateJson` check one without creating a listener.
- `ReloadFile` / `ReloadJson` replace the rules of a running server in one step; a configuration with a mistake throws and leaves the rules as they were.
- `MaxReceivedRequests` and `MaxConnectionRecords` cap what a long-running server keeps. Both are unlimited by default, as before.
- `RequestReceived` is raised for every request before its response is sent, and `ToJson()` gives it as one line of JSON. `MockServer.Listener` returns the listener of a server.

## 🐛 Fixed
- `WaitForConnectionAsync()` and `WaitForConnectionsAsync()` could return before a `ConnectionOpened` handler had run. They now complete after the handlers have returned, so a handler must not wait for something the test does after the wait.
- A `Log` callback that waited for another thread calling `Start()`, `Stop()`, `RefuseConnections()` or `AcceptConnections()` deadlocked, because the server logged while holding a lock.
- `RecordingProxy.Stop()` and `Dispose()` hung when called from the proxy's own `Log` callback.
- `rony record`, stopped before any client connected, wrote an empty recording. It now prints a message and writes nothing.
- `rony record --force` with an existing `--out` file failed on Linux and macOS.
- `rony run` with a Unix socket path that is too long or in use ended with exit code 1 and the runtime's own message. It is now exit code 2 with a message naming `server.path`.
